## Project Overview

Karma Maze is a game I built for the Reddit Puzzles & Games Hackathon that runs directly inside Reddit. Players guide a Snoo through a procedurally generated maze, using karma as both currency and score, and compete for a spot on the leaderboard.

<MediaContainer src="/projects/karma-maze/gameplay.png" alt="Karma Maze gameplay" />

## Design and Development Process

I wanted the whole thing to feel unmistakably Reddit - Snoo as the character, karma driving the core loop, that kind of thing - so a lot of early decisions were about tying the mechanics back to stuff Reddit users already understand.

### Early Development

I started with wireframes and prototypes to nail down the core loop before touching visuals. Getting the maze generator to reliably spit out solvable mazes took a fair amount of trial and error, and I spent a good chunk of early dev just on UI and performance.

<MediaContainer src="/projects/karma-maze/early-development.png" alt="Karma Maze early development screenshots" />

### Procreate and Visual Design

I hand-drew all the game assets in Procreate - karma orbs, maze tiles, all of it - trying to keep things readable at a glance while still fitting Reddit's visual style.

<MediaContainer src="/projects/karma-maze/procreate-design.png" alt="Karma Maze Procreate visual design" />

## Challenges Faced

The maze generator was the biggest headache early on - it kept producing mazes with no valid path through, which meant a lot of debugging before it was reliable. Reddit's API had its own learning curve too, especially around keeping karma updates and auth in sync in real time. Performance was another constant balancing act since the game needed to run fine on both desktop and mobile. And translating the Procreate art into assets that actually looked good in-game took more passes than I expected.

## Technical Implementation

I built Karma Maze on Devvit, Reddit's dev platform, which made hooking into the Reddit ecosystem straightforward. Mazes are procedurally generated so no two playthroughs are the same. The game is written in TypeScript, with Redis handling real-time score tracking and leaderboards, and it authenticates and reads karma straight from Reddit's own APIs.

## Game Features

### Core Gameplay Mechanics

Players move through the maze with keyboard or touch controls, collecting karma to open doors and get past obstacles. Later mazes add traps and fake exits to keep things from getting predictable.

### Progression and Replayability

Since every maze is generated fresh, there's a reason to keep coming back and chasing a better leaderboard spot.

### Platform Integration

Because it runs natively inside Reddit, players can jump in straight from a subreddit without leaving the app - no separate download or account needed.

## Future Development

I'd like to add daily challenges, new power-ups, and tougher traps to give players more reasons to keep playing, plus more maze themes and some accessibility improvements.

## Final Thoughts

Karma Maze was my first real attempt at building something that felt native to a platform instead of just embedded in it. Getting a real game to live comfortably inside Reddit's ecosystem, karma system and all, was harder than I expected going in, but that's also what made it fun to build.
